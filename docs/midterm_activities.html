Activity #1 – Variables

Code: Analyzed the Student class structure, tracing how primitives like int grade are stored in the stack, while objects like Student are stored in the heap with references like s1, s2, s3 pointing to heap objects.

Samples: Student s1 = new Student("John", 85); Student s2 = new Student("Maria", 90); Student s3 = s2; s3.name = "Ana";

Explanation: s3 = s2 copies the reference, not the object—so when s3.name = "Ana" runs, it modifies the same object s2 points to, reinforcing how OOP references interact in memory.

Activity #2 – Operators

Code: Implemented and traced arithmetic, relational, and logical operators in decision structures.

Samples: if (grade >= 75 && attendance >= 90) pass = true; else pass = false;

Explanation: Operators enabled conditional logic based on multiple inputs, ensuring correct program behavior under varying conditions.

Activity #3 – ATM with Transaction Counter

Code: Built an ATM system with deposit, withdrawal, and balance inquiry, tracking daily transactions using a counter.

Samples: public void deposit(double amount) { balance += amount; transactionCount++; }

Explanation: Encapsulation ensured data integrity, while the transaction counter demonstrated state management across method calls.

Activity #4 – Student Payment System with Validation Counter

Code: Created a student payment system validating input amounts and tracking failed attempts.

Samples: if (amount > 0 && amount <= balance) processPayment(); else invalidAttempts++;

Explanation: Input validation improved robustness, and the counter reinforced error handling best practices in OOP design.

Activity #5 – Personal Expense Tracker

Code: Developed a tracker managing income, expenses, and categories using arrays and classes.

Samples: expenseList.add(new Expense("Food", 150.00)); totalExpense += expense.amount;

Explanation: Using arrays and objects simplified data organization, while the tracker demonstrated real-world application of OOP principles.
